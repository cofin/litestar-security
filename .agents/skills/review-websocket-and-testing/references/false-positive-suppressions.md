# False-Positive Suppressions: WebSocket & Testing Review

Suppress and do not report findings matching these intentional patterns:

- **FP-WST-01 (Redacted one-time query-parameter connect-token extraction)**: Extracting a single-use, route/origin/epoch/policy-bound connect token from `WebSocketSecurityConfig.connect_token_query_parameter` (`"connect_token"` default) with `WebSocketHandshake.connect_token` marked `field(repr=False)` and `IssuedWebSocketConnectToken.__repr__` redacted is the intentional browser-compatible handshake carrier, while `RESERVED_QUERY_PARAMETERS` rejects reusable URL credentials (`access_token`, `authorization`, `bearer`, `jwt`, `token`).
- **FP-WST-02 (`InMemorySecurityBackend`, seeded `InMemoryOIDCSessionLogoutStore`, & `StoreRateLimiter`)**: Classes in `src/litestar_security/testing.py` are shipped test-kit doubles isolated from runtime imports (`R5`). Seeded `InMemoryOIDCSessionLogoutStore` fixtures (`oidc_logout_store` / `collaborators.build_security_environment()`) intentionally sit outside `collaborators.BACKEND_STORE_ATTRIBUTES`, and `StoreRateLimiter` (`RateLimiter`, verified via standalone `assert_rate_limiter_conformance`) sits outside `InMemorySecurityBackend.__slots__` and `StoreConformanceFactories`.
- **FP-WST-03 (`src/tests/helpers/typing.py` static checks)**: Typing helper functions are verified by `mypy` and `pyright` rather than runtime pytest assertions.
- **FP-WST-04 (Neutral fake token strings in tests)**: Neutral dummy strings (`"fake-oauth-access-token"`, `b"k" * 32`, and targeted `# noqa: S105` / `# noqa: S106` comments on non-secret protocol constants) satisfy `prek` hooks (such as Ruff `S105`/`S106`).
- **FP-WST-05 (Direct `testing.py` exports & `_OAUTH_EXPORTS`-only `__getattr__`)**: `src/litestar_security/testing.py` exports all 15 conformance stores and suites directly in `__all__` without lazy gating so conformance works without optional extras installed, while `src/litestar_security/__init__.py.__getattr__` resolves only `_OAUTH_EXPORTS` so `litestar_security.testing` stays unimported under `R5` (Ruff `TID251` and `tools/check_import_boundaries.py`).
