# Accounts False-Positive Suppressions

Do not flag the following intentional patterns in `src/litestar_security/accounts/`:

- **FP-ACC-01 (Exception suppression & `issue_absent()` in `RecoveryTokenService.request` & `VerificationTokenService.resend`)**: `RecoveryTokenService.request` and `VerificationTokenService.resend` intentionally execute `issue_absent()` on missing/ineligible accounts, catch and suppress store/delivery exceptions, and return `202 Accepted` (`LifecycleAccepted`) so attackers cannot probe account existence or trigger distinguishable timing or error responses.
- **FP-ACC-02 (Dummy password hash verification on missing account in `PasswordLoginService.authenticate`)**: Invoking `await self.hasher.verify(None, password)` when `AccountLookup.find_for_login` returns `None` (reached via `LocalAuthService.session_login` and `LocalAuthService.token_login`) is a deliberate timing-side-channel mitigation.
- **FP-ACC-03 (Predecessor refresh token accepted within `receipt_window` via `Idempotency-Key` & store `sealed_receipt`)**: Allowing a just-rotated refresh token to recover the original `TokenPair` when the client sends a matching `Idempotency-Key` header within `receipt_window` (`<= 30s`, `RefreshReceiptReplay`) prevents multi-tab race disconnects without minting extra tokens, while failing closed and revoking the family if receipt unsealing fails.
- **FP-ACC-04 (Runtime controller imports in `accounts/controllers/{_local.py,_mfa.py}`)**: `Request`, `SecurityContext`, `Principal`, `LocalAuthService`, and `WireStruct` types are imported at module top-level because Litestar resolves controller route signatures at runtime and `from __future__ import annotations` is banned.
- **FP-ACC-05 (`sign_count == 0` transitions & `CloneRiskPolicy.AUDIT_ONLY` in `PasskeyService`)**: Synced passkeys legitimately emit `sign_count == 0` on every assertion (`0 -> 0` and `0 -> >0` are allowed); `_passkeys.py` flags `clone_risk` only when `credential.sign_count > 0 and verified.sign_count <= credential.sign_count`, and under `CloneRiskPolicy.AUDIT_ONLY` records `clone_risk=True` and emits `OUTCOME_CLONE_RISK` without rejecting the login.
- **FP-ACC-06 (Optional third-party symbols imported from `litestar_security.typing`)**: Importing `Argon2PasswordHasherEngine`, `pyotp`, or `webauthn` helpers from `litestar_security.typing` (backed by `_typing.py` fallback shims and `_module_blocked()`) is required so module-level runtime annotations evaluate cleanly without `from __future__ import annotations`.
