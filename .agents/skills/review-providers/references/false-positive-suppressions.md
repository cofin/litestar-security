# False-Positive Suppressions: Providers Review

Suppress and do not report findings matching these intentional patterns:

- **FP-PRV-01 (Unverified JWT routing pre-inspection in `CompositeBearerConfig`)**: Routing selector inspection in `_bearer.py` (`parse_unverified_jwt_route`) checks unverified `typ`, `iss`, and `aud` (never `kid`) strictly to select candidate `BearerTokenSlot`s via `BearerSlotSelector`; full cryptographic signature and claim verification always executes inside the matched `BearerTokenSlot.verifier` (`JWTVerifier`).
- **FP-PRV-02 (`OAuthProviderClient._pinned_endpoint` literal IP URL rewrite + `sni_hostname`)**: Connecting to the verified public IP literal with `Host` header and `extensions["sni_hostname"]` prevents DNS rebinding between resolution and socket connection (`HttpxJWKSFetcher` and `OIDCDiscoveryClient` validate resolved DNS IPs and stream the original HTTPS URL).
- **FP-PRV-03 (`asyncio.shield` on shared JWKS refresh task)**: `CachedJWKSProvider._refresh_singleflight` shields `coordination.refresh.task` so cancelling one caller does not abort an in-flight JWKS refresh awaited by concurrent requests.
- **FP-PRV-04 (`IssuedAPIKey(key_id=..., value=...)` returned once on issue/rotate)**: Returning the raw key via `IssuedAPIKey.value` on `issue()`/`rotate()` is the sole moment callers can view the key; stores persist only `APIKeyState.digest`.
- **FP-PRV-05 (`BufferedAPIKeyUsage` deferred flush & capacity drop)**: Usage tracking via `APIKeyUsageSink.record(key_id=..., used_at=...)` is non-authoritative telemetry that coalesces per `key_id`, drops new entries when `len(_pending) >= capacity`, and flushes on `flush()` or shutdown (`BufferedAPIKeyUsage.close()` / `APIKeyService.close()`).
- **FP-PRV-06 (`APIKeyConfig(accept_authorization_bearer=True)` outside `CompositeBearerConfig`)**: `_APIKeyCredentialSlot` intentionally stays on its dedicated `"api-key"` slot while `AuthenticationRegistry._coordinate_bearer_slots` sets `excluded_prefixes` on `_BearerCredentialSlot` (or wraps custom Bearer slots in `_PrefixExcludingBearerSlot`), and `_plan_uses_bearer` inspects `additional_security_schemes` (`APIKeyBearer`) for RFC 9728 `WWW-Authenticate: Bearer` discovery challenges.
