# Review Checklist: Runtime, Policy, Guards, & Wire DTOs

Verify each invariant when reviewing changes to the runtime and policy layer:

- [ ] **RUN-01 (Runtime annotation resolution & optional-extra decoupling)**: Does every Python file omit `from __future__ import annotations` (`types: [python]`), keep DI/route/DTO types imported at module scope, preserve `MissingDependencyError` `_EXTRAS` (`argon2->argon2`, `pyotp->mfa`, `webauthn->passkeys`) in `_typing.py`, and keep `accounts/__init__.py` annotation exports eager with instantiation-time extra enforcement?
- [ ] **RUN-02 (Slotted contracts & `MappingProxyType` defaults)**: Do immutable domain/evidence/snapshot/policy value objects use `@dataclass(frozen=True, slots=True)` with `default_factory=lambda: MappingProxyType({})`, mutable orchestrators (`SecurityConfig`, `RouteCompiler`, `PolicyCompiler`, `BlockingCallRunner`, `_PrefixExcludingBearerSlot`) use `@dataclass(slots=True)`, and non-dataclass runtime classes define `__slots__`?
- [ ] **RUN-03 (`resolve_authorization` restriction narrowing & guard composition)**: Does `resolve_authorization` ensure `CredentialRestrictions(scopes, roles, capabilities, tenant_ids, resources)` never widen `AuthorizationSnapshot` or mutate `attributes`, and do `guards.py` predicates compose via `requires_all_of`, `requires_any_of`, `requires_one_of`, `requires_at_least`, and `requires_assurance` (`_AssurancePredicate`)?
- [ ] **RUN-04 (`public()` vs. `exclude()` CSRF, middleware, & OpenAPI semantics)**: Does `public()` emit `[{}]`, populate anonymous `scope["user"]`/`scope["auth"]`, and set `opt[csrf_exclude_key] = True` unless `csrf_required=True` is set on the HTTP handler, while `exclude()` emits `[{}]`, leaves native CSRF untouched unless `csrf_required=True`, and sets `plan.bypass_authentication=True`?
- [ ] **RUN-05 (Slot ownership, `_PrefixExcludingBearerSlot`, & RFC 9728 challenges)**: Are duplicate physical `CredentialSlot` owners rejected at startup with `ImproperlyConfiguredException` unless composed via `CompositeBearerConfig`, does `AuthenticationRegistry._coordinate_bearer_slots` wrap custom non-dataclass `authorization.bearer` slots in `_PrefixExcludingBearerSlot`, and does `SecurityMiddleware._plan_uses_bearer` inspect `additional_security_schemes`?
- [ ] **RUN-06 (Static & runtime import boundaries)**: Does runtime code stay free of `inspect.isawaitable` (`R4`), `litestar_security.testing` imports (`R5` + `TID251`), and banned adapter imports (`TID251`), with `__init__.py` lazy loading via `_lazy.py` scoped only to `_OAUTH_EXPORTS`?
- [ ] **RUN-07 (`WireStruct`, `WireDTO`, error schemas, & secret redaction)**: Do wire schemas subclass `WireStruct(frozen=True)` (`WirePolicy(rename, forbid_unknown_fields)`, `MAX_NESTED_DEPTH = 4`), bind `cache_key = (*name_key, shape)` before indexing `_transfer_models`, restrict `WireUnionDTO` / `union_wire_dto` to responses, accurately project `RouteError` / `ProblemDetail` (`ProblemDetailsPlugin(enable_for_all_http_exceptions=True)`) / `RaisedErrorSchema`, and redact secrets (`SecretStr`, `field(repr=False)`, or custom `__repr__`)?
- [ ] **RUN-08 (Security headers & `__Host-` binding cookie validation)**: Does `configure_security_headers` integrate via `response_headers`, `before_send`, and `csp_nonce` DI (no headers middleware), and do `SessionBindingConfig._validate_binding_cookie_scope` and `OAUTH_BINDING_COOKIE_NAME` enforce `__Host-` (`secure=True, path="/", domain=None`)?
- [ ] **RUN-09 (`CORE_COVERAGE` 100% branch coverage & test tier placement)**: Are all branches in `authentication.py`, `guards.py`, and `context.py` covered across `src/tests/unit/` (strictly free of `Litestar`, `TestClient`, and `AsyncTestClient` instantiations) and `src/tests/integration/`?
