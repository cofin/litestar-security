# False-Positive Suppressions: Accounts Review

Suppress and do not report findings matching these intentional patterns:

- **FP-ACC-01 (Exception suppression & `issue_absent()` in `RecoveryTokenService.request` & `VerificationTokenService.resend`)**: Performing a parity `issue_absent()` call for missing/ineligible accounts, swallowing store/delivery errors, and returning uniform `202 Accepted` (`LifecycleAccepted`) is required to prevent account enumeration.
- **FP-ACC-02 (Dummy password hash verification on missing account in `PasswordLoginService.authenticate`)**: Calling `await self.hasher.verify(None, password)` when `AccountLookup.find_for_login` returns `None` (reached via `LocalAuthService.session_login` / `token_login`) is an intentional timing-side-channel mitigation.
- **FP-ACC-03 (Predecessor refresh token replay within `receipt_window` via `Idempotency-Key` & store `sealed_receipt`)**: Returning the already-minted `TokenPair` within `receipt_window` (`<= 30s`) when the client presents a matching `Idempotency-Key` header against store-persisted `sealed_receipt` bytes (`RefreshReceiptReplay` / `RefreshRotationStatus.IDEMPOTENT_REPLAY`) is the concurrency design for interrupted rotations and multi-tab clients.
- **FP-ACC-04 (Top-level runtime imports in `accounts/controllers/{_local.py,_mfa.py}`)**: Required for Litestar runtime signature inspection because `from __future__ import annotations` is banned.
- **FP-ACC-05 (`sign_count == 0` transitions & `CloneRiskPolicy.AUDIT_ONLY` in `PasskeyService`)**: Synced passkeys legitimately emit `sign_count == 0` (`0 -> 0` and `0 -> >0` are allowed); `_passkeys.py` sets `clone_risk` only when `credential.sign_count > 0 and verified.sign_count <= credential.sign_count`, and under `CloneRiskPolicy.AUDIT_ONLY` records `clone_risk=True` and emits `OUTCOME_CLONE_RISK` without rejecting.
- **FP-ACC-06 (Optional SDK symbols imported from `litestar_security.typing`)**: Importing `argon2`, `pyotp`, and `webauthn` symbols from `litestar_security.typing` (backed by `_typing.py` fallback shims and `_module_blocked()`) is intentional so runtime annotations evaluate without `from __future__ import annotations` when optional extras are absent.
