# Review Checklist: Local Accounts, Sessions, High-Assurance Auth, & Rate Limiting

Verify each invariant when reviewing changes to `src/litestar_security/accounts/`:

- [ ] **ACC-01 (Timing & response enumeration resistance)**: Does `PasswordLoginService.authenticate` resolve identifiers via `AccountLookup.find_for_login` and execute dummy `hasher.verify(None, password)` on unknown accounts, and do `RecoveryTokenService.request` / `VerificationTokenService.resend` invoke `issue_absent()`, swallow store/delivery errors, and return uniform `202 Accepted` (`LifecycleAccepted`) responses?
- [ ] **ACC-02 (Dual-cookie session binding, `__Host-` flags, & fixed expiry)**: Are session binding cookies verified with `hmac.compare_digest`, are `__Host-` constraints (`secure=True`, `path="/"`, `domain=None`) enforced in `_validate_binding_cookie_scope`, does `authenticate()` enforce `record.expires_at == authentication.expires_at` (no sliding `expires_at` renewal), and is `accounts.touch()` throttled only for `last_seen_at` via `touch_interval`?
- [ ] **ACC-03 (Refresh family reuse revocation & store receipt AAD)**: Does replaying a rotated refresh token without a valid `Idempotency-Key` header inside `receipt_window` (`<= timedelta(seconds=30)`) emit `RefreshRotationStatus.REPLAY_DETECTED` and revoke the full `family_id`, does `RefreshTokenCodec.digest_idempotency_key` match store-persisted `sealed_receipt` bytes (`RefreshReceiptReplay`), and does `_receipt_aad` bind `(account_id, expiry, family_id, idempotency, key_id, security_epoch, token_id, version="rr1")`?
- [ ] **ACC-04 (Domain-separated purpose tokens vs. MFA login challenges)**: Does `PurposeTokenCodec` bind `TokenPurpose` (`INVITATION`, `VERIFICATION`, `RECOVERY`) in HMAC digests consumed atomically via `RegistrationStore.register`, `VerificationTokenStore.consume_and_verify`, and `RecoveryTokenStore.consume_and_reset`, while password-login MFA challenges stay isolated in `MFALoginService` (`MFALoginChallengeStore.consume`)?
- [ ] **ACC-05 (At-rest MFA secret encryption, peppered recovery codes, & Argon2 workers)**: Does `AESGCMSecretProtector` store `ProtectedSecret(ciphertext: bytes, key_version: str)` (`nonce + ciphertext`, no `"v1:"` prefix), does `MFAService.consume_recovery_code` compute `RecoveryCodePepper` HMAC digests and delegate constant-time verification to `MFAStore.consume_recovery_code`, and does `Argon2PasswordHasher` offload work via `_run_password_worker` using `WorkerLimits.crypto_limiter`?
- [ ] **ACC-06 (WebAuthn challenge single-use & sign-count clone-risk policy)**: Are `WebAuthnChallenge` records consumed once via `WebAuthnChallengeStore.consume`, and does `PasskeyService` evaluate `clone_risk = credential.sign_count > 0 and verified.sign_count <= credential.sign_count` (rejecting under `CloneRiskPolicy.REJECT`, and recording `clone_risk=True` + emitting `OUTCOME_CLONE_RISK` without rejecting under `CloneRiskPolicy.AUDIT_ONLY`)?
- [ ] **ACC-07 (Step-up grant scoping & expiry)**: Does `StepUpService` persist `StepUpGrantState(grant_digest, transport_digest, principal_id, security_epoch, purpose, methods, traits, authenticated_at, expires_at)` using `clock: Callable[[], datetime]`, consume atomically via `StepUpStore.consume`, and return `AuthenticationEvidence(mechanism="step-up", slot="mfa", authenticated_at=record.authenticated_at, expires_at=record.expires_at, methods=record.methods, traits=record.traits | frozenset({f"purpose:{purpose}"}))`?
- [ ] **ACC-08 (`_refresh.py` 100% branch coverage & store conformance sync)**: Does `src/litestar_security/accounts/_refresh.py` retain `100%` branch coverage (`CORE_COVERAGE`), and are store protocol edits mirrored in `InMemorySecurityBackend` and `assert_security_backend_conformance` in `src/litestar_security/testing.py`?
- [ ] **ACC-09 (Optional-extra decoupling via `litestar_security.typing`)**: Do pure `accounts` protocols, records, `AESGCMSecretProtector`, `StepUpService`, `PasskeyService` (with custom `WebAuthnVerifier`), `LocalAuthConfig` (with custom `PasswordHasher`), and `controllers` resolve without `argon2`, `pyotp`, or `webauthn`, keeping `_CONTROLLER_EXPORTS` lazy in `accounts/__init__.py` and gating only `Argon2PasswordHasher`, `MFAService`, `MFALoginService`, and `PyWebAuthnVerifier` via `ensure_argon2` / `ensure_pyotp` / `ensure_webauthn`?
